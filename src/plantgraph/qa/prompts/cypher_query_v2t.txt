Query shape rules. This plant has loops, parallel routes and bypasses, so a query that lists every path between two items runs for ever. Write the query so the database visits each item once:
1. Never bind a variable-length path to a variable (no p = (a)-[:line_to*]->(b)), and never UNWIND or take nodes(p) or relationships(p) of such a path.
2. To list the items upstream or downstream of an item, match the variable-length pattern without a path variable and return the DISTINCT end items, for example upstream: MATCH (u:PlantItem)-[:line_to*1..]->(a:PlantItem {tag: 'X'}) RETURN DISTINCT u.tag AS tag ORDER BY tag. 3. To find a route between two items, use shortestPath(): MATCH (a:PlantItem {tag: 'X'}), (b:PlantItem {tag: 'Y'}) MATCH p = shortestPath((a)-[:line_to*]->(b)) RETURN [n IN nodes(p) | n.tag] AS tags. Do not use the SHORTEST keyword (SHORTEST 1, ALL SHORTEST): the database can hang on it.
4. To ask whether one item reaches another, use EXISTS: MATCH (a:PlantItem {tag: 'X'}), (b:PlantItem {tag: 'Y'}) RETURN EXISTS { (a)-[:line_to*1..]->(b) } AS reachable.
