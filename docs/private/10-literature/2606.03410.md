## Claim
First open benchmark for VLMs on complex engineering diagrams. Also — and this is the part that matters to us — shows that token-overlap metrics **under-report model capability by 2–6×** on technical text.

## Method / dataset
10 US military service and repair manuals, **6,940 pages**. Five-stage automated extraction: layout analysis (Unstructured) → figure–table matching → 200 DPI rasterization → table extraction with Claude Sonnet 4.5 → validation. Human check on 50 stratified TSVs gave **98.7% item extraction accuracy**.

- **Task 1** — structured parts-table extraction. Image in, JSON out (`item_no`, `part_number`, `description`, `quantity`). 2,056 pairs, 494 in the benchmark subset.
- **Task 2** — free-form VQA on a composite image. **60 expert-written QA pairs** over 12 diagrams.

## Metrics — the reusable part
- **Recall@all** = |G ∩ Ĝ| / |G| — fraction of ground-truth items recovered, matched on normalized item number. Detection, independent of description quality.
- **Token F1_pen** — token-overlap F1 on matched descriptions, multiplied by Recall@all so misses are penalized.
- **Semantic Similarity_pen** — same, but cosine over `all-MiniLM-L6-v2` embeddings. Paraphrase-invariant.
- **LLM-as-judge, 1–5**, with a **cross-judge design: no model scores its own outputs.**

## Results
Task 1 (n=494): Recall@all **0.61–0.87** but Token F1_pen only **0.03–0.18**. Best is Claude Opus 4.7 + CoT (0.865 / 0.179 / 0.360).

Task 2 (n=60): best LLM-judge score across every model and condition is **3.20/5** (Claude Opus 4.7 + CoT). A consistent factual-reasoning gap everywhere.

**The metric finding:** Semantic Similarity_pen runs 2–6× higher than Token F1_pen throughout. Cause — models write "self-locking nut" where the manual says "NUT, SELF-LOCKING, HE". Identical meaning, near-zero token overlap.

## Relation to this dissertation
The outlier on the reading list: no graphs, military manuals not P&IDs, VLM benchmarking not retrieval. Its value is **methodological**, and it is substantial.

It empirically confirms the BLEU/ROUGE skepticism recorded in the earliest project notes — now citable rather than an opinion. It also supplies the evaluation design:
- structural recall separated from description fidelity
- penalized metrics so misses cannot be hidden
- **cross-judge LLM evaluation** — stricter than ChatP&ID, which judges with a model from the same family as those tested

Its weakness is our opening: **models find things but describe them badly**, and no diagram in it links to another. Nothing here is cross-document.

## Reusable
Recall@all and the penalized-metric pattern; the cross-judge protocol; the released harness and per-sample outputs (CC BY 4.0, HuggingFace `enginuity2025/enginuity-bench`, GitHub `abhishek-predii/enginuity-bench`) as a model for how to release ours.
