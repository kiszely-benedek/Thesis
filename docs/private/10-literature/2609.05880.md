## Claim
Recover an explicit process graph from a P&ID raster, then force a VLM to answer topology questions only through
**seven read-only graph operators** with cited evidence; on their new TopoPID-VQA (3,000 questions) this lifts pooled
exact match from 36.7–41.3 % (image-only) to 74.3–76.0 % for three 4–8B open VLMs (Abstract, Table 1).

## Method
**Stage 1 — graph recovery (§4, A.1).** Tiled YOLO11s symbols (det. F1 0.983), EfficientNet-B0 U-Net solid/dashed
masks (Dice 0.982), YOLO-text + fine-tuned TrOCR (det. F1 0.833). Deterministic topology: skeletonise, intersection
noding, per-sheet adaptive junction snap `j_eff = min(0.12ℓ, max(8, g+0.05ℓ))` (fixed 10 px collapses exact edge
F1 to 0.193, Table 9), symbol attach within 120 px, "first-symbol walk" emitting **undirected** process edges, then
geometric tag association. Output `G_auto`: typed symbol nodes (class, optional tag), undirected edges, line tags. An
optional dashed signal-edge layer exists but **no question uses it** (§5.3).

**Stage 2 — Graph-Grounded Harness (§4, A.9).**
- *Seed step outside the tools:* VLM entity extraction; coloured mark letters A/B/C on the image are detected and
  snapped to the nearest `G_auto` node; tag strings in Q are linked through OCR tags (optional VLM crop to
  disambiguate). A "seed-listing helper" (`list_seeds`, Fig. 8) gives these to the planner; "not counted among the
  seven tools".
- *Seven tools (Table 16, verbatim semantics):*
  | Tool | Args | Returns |
  |---|---|---|
  | `node_info` | `{id}` | class, OCR tag, degree, sheet coordinates of one node |
  | `neighbors` | `{id}` | one-hop neighbour ids with class, tag, degree, coordinates |
  | `find_nodes` | `{attr, match, value}` | all ids whose class or tag equals / case-insensitive-prefix-matches value, with count and a compact attribute table |
  | `bfs` | `{id, ids?, exclude_ids?, max_hops?}` | hop distances from id; `ids` restricts the returned map; unreachable → `null` |
  | `shortest_path` | `{a, b, exclude_ids?}` | node path a..b inclusive, or `null`; `exclude_ids` not traversed |
  | `edge_exists` | `{a, b}` | boolean: undirected process edge present — "the only tool that returns a boolean verdict" |
  | `set_op` | `{op, a[], b[]}` | intersect / union / diff on id lists |
  Tools return facts, "never a yes/no verdict on Q"; "counting, comparison, thresholding, and routing" stay in the
  model's chain-of-thought. The planner "never receives a dumped adjacency list" (§4).
- *Loop and budget:* "iterates until it emits a final answer or exhausts a six-turn budget (at least one tool call
  required before the answer is accepted)" (A.9); Fig. 8: "Missing evidence starts another turn (cap six)". **What
  is answered when six turns run out is not stated**, nor how many items hit the cap.
- *Result referencing:* "Each tool result gets an identifier that the final answer must cite" (A.9). The identifiers
  serve **citation/audit**; tool arguments are node ids and id lists (`set_op` takes `a[]`, `b[]`), so composition
  happens by the model copying ids, not by passing a result handle.
- *Answer contract (§4):* (1) no final answer without ≥ 1 tool call; (2) "Every named entity in Q must be queried
  through a tool before answering"; (3) for closed counting questions the number of cited entities must equal the
  reported count. Fixed final schema: interpretation, tool-step references, supporting entity ids, typed answer;
  integers clamped to ranges parsed from Q, strings snapped to enumerated options. A contract reject triggers "at most
  one forced re-ask" (A.4).
- *Models:* Qwen3-VL-4B-Instruct, Qwen3-VL-8B-Instruct (4-bit NF4), Gemma-4-E4B-it (W4A16); planner turns capped at
  256–512 new tokens (A.4).

## Evaluation
- **Documents:** Digitize-PID, 500 **synthetic** single-sheet rasters, 32 symbol classes; split 350/50/100; all QA on
  the **100 test sheets**. Avg ~118 symbols and 338 undirected process edges per sheet (§5.2). Every item is one sheet
  with its own frozen `G_auto`. No off-page connectors, no multi-sheet, no cross-document anything (searched the full
  text for off-page / connector / multi-page / cross-sheet: no hits).
- **Questions:** TopoPID-VQA, 3 tiers × 100 sheets × 10 = **3,000**; 28 template families (8 easy / 10 medium / 10
  hard, Tables 17–19), e.g. `connected_process`, `reachable_within_k`, `same_network`, `path_avoiding_type`,
  `counterfactual_reconnect`, `distance_bucket`. Answer types: 1,998 bool / 601 int / 401 string (Table 20). Only
  792 unique question strings, ~511 after masking marks and tags (A.13). No paraphrase stage.
- **Ground truth:** computed programmatically on `G_oracle` (GT boxes + Digitize GT connectivity); "Gold answers never
  pass through a language model" (A.10). No human-written questions.
- **Runs:** one greedy decode per call, "Each question is evaluated once" (A.4). Sheet-clustered percentile bootstrap,
  B = 10,000, paired Δ CIs (A.5).
- **Metric:** exact match; boolean P/R/F1 (positive = true).
- **Results (Table 1, pooled, Img. → Agent):** Qwen3-VL-4B 40.1 ± 1.6 → 76.0 ± 1.8 (+35.9); Qwen3-VL-8B 41.3 ± 1.7 →
  75.1 ± 1.4 (+33.8); Gemma-4-E4B 36.7 ± 1.6 → 74.3 ± 1.5 (+37.6). Hard tier agent: 63.9 / 60.9 / 65.8.
  Gold-query ceiling (gold entities + query structure on `G_auto`, no VLM) ≈ 88.9 % pooled (§5.3).
- **Floors (Table 21):** majority 48.1 %, random 35.6 % pooled — **the image-only baseline sits below the majority
  floor** (A.12), so part of the "lift" is over a below-chance baseline.
- **Faithfulness (A.6, Table 8):** fabricated-true rate on 708 gold-false topology booleans, pooled Img. → Agent:
  37.0 → 16.5, 50.8 → 18.8, 54.5 → 21.0. Among wrong harness answers, 45.8 / 33.4 / 52.6 % cite non-empty evidence
  ("faithful-but-wrong").
- **Substrate (Table 2):** exact edge F1 0.742 (P 0.677, R 0.820), connectivity-consistency 0.958, attributed 0.801.
- **Latency / cost:** **not reported for QA.** Only Stage-1 wall-clock (Table 10): 1.2 s/sheet symbols, 4.6 s lines,
  22.7 s text+OCR on 2 × 16 GB GPUs, ~4 min CPU graph build per 100 sheets. Local models, so no $ figure.
- **Baselines:** image-only only. No graph-in-prompt (ContextRAG-style), no text-to-Cypher, no harness ablation.

**Claimed vs demonstrated.** Claimed: grounding through tools "raises answer reliability on topology questions"
(§1). Demonstrated: on synthetic single sheets, a bundled harness (graph + tools + seeding + contract) beats a VLM
reading pixels that scores below the majority floor; which component carries the gain is untested (§6).

## Relation to this dissertation
**Does not take our territory** (single-sheet, synthetic, no cross-sheet, no strategy-vs-scale comparison). It **does
take the pattern** of ADR-0034 at single-sheet level: a bounded agent over a small set of generic, fact-returning graph
primitives, type-agnostic, with a six-step cap. ADR-0034 and the thesis must cite it as the P&ID precedent.

| | 2609.05880 harness | our `graph_agent` (ADR-0034) |
|---|---|---|
| Graph | one synthetic sheet from raster, ~118 nodes, **undirected**, process edges only | cross-sheet **item graph**: off-page stub pairs contracted (`via` record), identity links merged; four **directed** relations (flow / signal groups); D100 / D1000 plant scale |
| Primitives | 7: `node_info`, `neighbors`, `find_nodes`, `bfs`, `shortest_path`, `edge_exists`, `set_op` | 6: `find`, `neighbours`, `traverse`, `path`, `filter`, `aggregate` |
| Mapping | `find_nodes`≈`find` (theirs: class or tag, equals/prefix; ours: `ItemFilter` label/class/unit/sheet/tag); `neighbors`≈`neighbours` (ours adds direction, relation group, filter); `bfs`≈`traverse` (theirs: hop distances, `exclude_ids`; ours: `stop_at`, `walk_only`, `max_hops`, direction); `shortest_path`≈`path` (ours reports sheets crossed, `directed`); `node_info` ⊂ our item records | — |
| Only theirs | `edge_exists`, `set_op`, `exclude_ids` | — |
| Only ours | — | `filter` over a prior result, `aggregate` (they leave counting to the model and check it via contract (3)) |
| Composition | result ids for **citation**; args are literal id lists | `$rN` **handles** passed as inputs |
| Entity grounding | done before the loop by a seed helper (marks + OCR tags) | the agent finds tags itself; unknown tags get an explanatory result (`missing_tag`); `hier_agent` adds a seed map |
| Budget | 6 turns; behaviour at exhaustion unstated; ≥ 1 tool call required | 6 steps + prompt cap 150,000 chars, observation cap 4,000, 2 errors, runaway, 120 s question deadline (ADR-0048, over-deadline = `TIMED_OUT`, scored wrong); **shared final step always runs** on what was gathered |
| Answer | typed schema, clamp/snap, evidence ids, one re-ask | shared final step identical across strategies |
| Baselines | image-only only | ContextRAG, CypherRAG, `cypher_agent` (iteration held equal), need-aware selection, cascade with Cypher tier 1 |
| Questions | 3,000 template, programmatic gold, 1 run | natural-language families incl. held-out families (ADR-0035) |
| Absent / unanswerable | none; "no reported calibration or abstention" | unknown-tag wording in the API; abstention is a thesis axis |

**What stays ours:** primitives over a resolved cross-sheet graph (connectors and identities hidden beneath the API),
directed flow vs signal relations, the typed-vs-free-form control with iteration held equal, held-out families, the
cascade cost/latency frontier, and the scale sweep. Their absence of any serialization or Cypher baseline means the
paper says nothing about the strategy-vs-scale claim.

## Limitations they admit (§6)
- "Digitize-PID is synthetic; scores do not measure shift to scanned plant drawings, handwritten redlines, or
  site-specific standards."
- "we ablate graph construction (Appendix A.7) but not the harness factors, so the reported lift is not attributed to
  individual components."
- "Exact edge F1 on G_auto is 0.742, so a wrong recovered edge can yield a faithful but incorrect tool answer."
- "There is no reported calibration or abstention; human review remains necessary for safety-relevant use."
- Future work (§7): "scanned plant sheets, harness-factor ablations, abstention, and TopoPID-VQA questions over the
  signal-edge layer." Multi-sheet is not even listed.

## Reusable / adoptable
1. **Gold-query ceiling** = run the canonical program with gold entities on the system's graph; separates substrate
   error from planner error. Our API-02 canonical programs can be reported exactly this way (per family, on the
   resolver's graph vs the gold plant).
2. **Answer-contract checks as diagnostics, not rejections:** % answers with zero tool calls; % questions whose named
   tags were never touched by a call (cheap from our `touched_keys` trace); count-vs-cited mismatch.
3. **Fabricated-true rate** on gold-false booleans and **faithful-but-wrong share** — computable from existing dumps,
   no paid run.
4. **Cluster bootstrap** (resample the unit that shares error — for us the question family or seed region, not the
   question) and **paired Δ CIs**; **majority/random floors per answer type**.
5. `set_op` / `exclude_ids`: our six primitives cannot intersect two handles or exclude a named item from a traversal
   (`stop_at` includes the stop item). Isolation / counterfactual questions ("if V-101 is closed, is T-2 still fed?")
   are P&ID-central. Per ADR-0034, do **not** add a tool mid-evaluation; if a held-out family fails for this reason,
   report it as the API boundary and name `set_op`/`exclude` as the fix. `edge_exists` needs no tool: it is
   `neighbours(A, where={tag: B})`.
6. Budget exhaustion: nothing to adopt — their behaviour is unstated, ours (always run the final step, log the stop
   reason) is better specified; report our stop-reason distribution, which they do not.
