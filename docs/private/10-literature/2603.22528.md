## Claim
An agentic GraphRAG framework over DEXPI P&IDs: graph representations improve accuracy 18% over raw images and cut token cost 85% versus ingesting the smart P&ID file directly.

## Method
DEXPI XML → **pyDEXPI** → **Neo4j labeled property graph**. pyDEXPI instances become nodes, compositional attributes become `has-*` edges, reference attributes (`send_to`, `control`) become relational edges, class hierarchy becomes node labels.

Three abstraction levels via condensation (prune domain nodes, collapse low-information nodes, drop non-process properties): **complete → process → conceptual**.

Semantic enrichment: GPT-4o writes a *local* and a *global* description per node; both embedded to 1024-d with Voyage-3.5-lite.

Single LangGraph agent picks between four tools:
- **ContextRAG** — serialize the condensed graph to GraphML, put it in the prompt. No retrieval.
- **VectorRAG** — cosine top-k over node embeddings. No traversal.
- **PathRAG** — vector-seeded, then LLM-guided hop-by-hop traversal (max breadth 2, max depth 3).
- **CypherRAG** — NL → Cypher → Neo4j → answer.

## Evaluation  ← the weak point
**One file** (`DEXPIEX01.xml` from the DEXPI standard), **19 QA pairs**, ground truth written by the authors "to the best of our knowledge", 2 runs per config, each tool limited to a single call with no iterative refinement.

> **Correction 2026-10-10** (quotes checked verbatim against the raw arXiv HTML, v1): "single call" describes the
> **evaluation**, not the **architecture**. The architecture is an iterative agent loop — §3.1 "Agentic framework":
> "The agent iteratively assesses whether the retrieved knowledge is sufficient to answer the user query. If
> additional context is required, the LLM may invoke additional GraphRAG methods until the information is sufficient
> or the predefined maximum number of tool calls is reached." The evaluation switches iteration off — §4.1
> "Configuration": "A tool limiter is added to limit the number of tool calls. Each tool can be called only once per
> test to evaluate its performance without iteration." (Same for CypherRAG in §6.2: "we limit the query generation to
> a single attempt without iterative refinement.") So the published numbers measure single-shot tools inside an agent
> designed to iterate; the maximum number of tool calls in deployment is not given. Cite it as "an iterative agent,
> evaluated with one call per tool", never as "a single-call system".

Categories: graph query single (8), graph query multi (2), path exploration (5), knowledge inference (3), summarization (1).

Metric: LLM-as-judge (GPT-5-mini) on 4 criteria — relatedness, completeness, correctness, coherence — 1–5, rescaled to 0–1, averaged. Plus cosine semantic similarity.

**Results (GPT-5-mini, conceptual graph):**

| Tool | Accuracy | Cost/task | Time |
|---|---|---|---|
| ContextRAG | **0.91** | $0.0044 | 24.3s |
| CypherRAG | 0.86 | $0.0016 | 39.4s |
| PathRAG | 0.83 | $0.0021 | 54.6s |
| VectorRAG | 0.82 | $0.0023 | 24.4s |
| Proteus file direct | 0.88 | $0.0342 | 52.0s |

GPT-5 + conceptual = **0.94** avg. Raw image = 0.76. Small open models collapse on ContextRAG (LLaMA3.1:8B 0.28, Qwen3:14B 0.43) because they cannot parse GraphML; VectorRAG/PathRAG recover them to ~0.6–0.72.

## Relation to this dissertation
This is the paper we are extending **and arguing against**. It owns single-sheet DEXPI→GraphRAG.

The headline — *retrieval is unnecessary, just stuff the condensed graph in the prompt* — holds only because 212 nodes condense to 53. At 100 pages × ~382 nodes ≈ 38,000 nodes (~10k conceptual), ContextRAG is not available at all. **Their ranking should invert at our scale, and that inversion is our thesis.**

## Limitations they admit
- "Relatively simple, high-resolution, single-page document... typical industrial P&IDs are far denser with more objects per page"
- CypherRAG degrades as graph size grows: "the LLM often struggles to identify specific path, necessitating multiple reasoning cycles" — i.e. they *predict* our result without measuring it
- Single-attempt tool calls, no feedback loops
- *(added 2026-10-10)* ContextRAG at multi-page scale, §6.2 "Strengths and limitations of tooling approaches",
  verbatim: "However, its primary limitation emerges when flowsheets span multiple pages; because the entire graph
  must be passed to the LLM for each inference, costs scale linearly with graph size. To mitigate this, we implemented
  a "topology mode" that passes only the lightweight structural framework without data attributes." — the authors
  name our setting as their headline method's limitation and do not measure it.
- Multimodal input misreads text (PSV pressure example)
