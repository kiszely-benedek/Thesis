# EXP-0004 on v2: identity across sheets when the tag is written differently

**Why a new note and not an appendix to §4.** `hierarchical-and-jev.md` holds three components (Hierarchical,
EXP-0004, the router) under one accepted ADR set. The v2 revision changes the corpora, the variant operators, two
deciders, the freeze method, and adds an end-to-end arm. Appended, §4 would describe two incompatible designs in one
section. §4 keeps its accepted text plus a pointer line; this note says what carries over (§1) and replaces the rest.

## 0. Question and link to the claim

At the registered v2 test seeds, with every reference occurrence's tag written as a variant:

1. **Resolution.** What identity P/R/F1 does each decider reach on the same candidate pairs, at what cost, separately
   for a variant family that was tuned on (format) and one that was not (naming), at ~100 and ~1,000 sheets?
2. **End to end.** How much of the frozen V2T-A cascade's sealed accuracy at 1,000 sheets (R5: 392/440 = 0.891,
   `EXP-0007-R5-sealed.md`) survives when tags vary and the resolver is exact, and how much a decider wins back?

Claim link: the R5 headline was measured with exact tags (ADR-0028). Cross-sheet identity is what makes 1,000 sheets
one plant graph. At H1000g2, **112 of 560** sealed questions have `k_identity > 0`; at H100g2, **97 of 560**
(count over `data/runs/exp0007/sealed/questions/*/questions.jsonl`, 2026-11-04, structural field only, no answers
read). Those are the questions whose evidence crosses a sheet boundary through a duplicated item. If identity breaks,
those questions are the ones at risk.

## 2.1 Context signals at 1,000 sheets

D1000g2, rate 1.0 (872 gold links, 1,034 blocked negatives): same unit 872/872 gold vs 357/1,034 negatives;
connector-joined sheets 660/872 vs 301/1,034; shared line number 0 vs 0; shared neighbour tag 0 vs 0; one side a bare
reference 872/872 vs 596/1,034.

**Reading.** The 357 same-unit negatives equal the 357 A/B-spare negatives of §2. At both sizes, then, the unit rule
leaves exactly the spares, and only the spare letter tells those apart. That is what D2's string score plus the §5.3
one-to-one rule must do. Shared line numbers carry no signal. The likely reason (reasoned, not checked) is that the
reference's local edges and the home's edges are different plant edges. Connector adjacency is weaker than the unit and goes into the card, not into D2's rule.
"One side is a bare reference" holds for every gold link. It is visible (property count) and already decides the
home (§5.3), but no decider rule uses it. A decider that did would exploit how our splitter draws references.

## 3. Variant generator (`benchmark/tag_variants.py`, new)

### 3.1 Shape

```python
class VariantConfig(BaseModel):          # frozen
    profile: Literal["exp0004"]
    families: tuple[Literal["format", "naming"], ...] = ("format", "naming")
    rate: float = Field(default=1.0, ge=0.0, le=1.0)
    seed: int                            # the corpus seed

class VariantDraw(BaseModel):            # frozen; gold side, never visible
    reference_key: str                   # "sheet:node_id", as in IdentityGroup.references
    family: Literal["format", "naming"]
    operator: str
    original_tag: str
    variant_tag: str

def apply_tag_variants(
    sheets: list[SheetGraph], manifest: SplitManifest, config: VariantConfig
) -> tuple[list[SheetGraph], SplitManifest, list[VariantDraw]]: ...
```

- A **post-split transform**: it rewrites `tag` on reference occurrences only and fills the existing
  `IdentityGroup.tag_variants` field (`benchmark/models.py`). Sheets, edges, connectors, groups and homes are
  otherwise unchanged. `splitter.py`, `SplitConfig` and the legacy `_tag_variant` are not touched, so RESOLVE-01
  stays reproducible and the variant copy has **exactly R5's split** (tested: manifest equal modulo tags).
- RNG per reference: `random.Random(f"{config.seed}:{reference_key}")`; it draws whether to vary (`rate`), the
  family (uniform over enabled families), then the operator (uniform over applicable operators in a fixed order).
  An operator that would leave the tag unchanged is not applicable.
- Equipment only (the resolver groups `EQUIPMENT_CLASSES`, `resolution/identity.py`). Home occurrences keep the
  canonical tag.

### 3.2 Operators on v2 equipment tags

| Family | Operator | `P-1203A` → | Grounding |
|---|---|---|---|
| format | `drop_separator` | `P1203A` | OPEN100 `RC-P102A` (no separator before the number) |
| format | `swap_separator` | `P 1203A`, `P.1203A` | ChatP&ID `SV 104.01` (space and dot styles) |
| format | `split_number` | `P-12-03A` | declared: unit and sequence written as two fields |
| format | `unpad_sequence` | `P-123A` (only if the sequence has a leading zero) | declared |
| format | `spare_separator` | `P-1203-A` (only with a spare suffix) | declared |
| format | `case` | `p-1203a` | legacy `_tag_variant` |
| naming | `class_synonym` | `PU-1203A`; `E-…` → `HX-…`; `K-…` → `C-…` | `P`/`PU`: OPEN100 `RCS-PU-102A` vs `RC-P102A` (verified, `open100-annotation.md` line 90); `HX`: OPEN100 `CVCS-HX-111` (reading unverified); `C`: this repo's own v1 prefix for `Compressor` (`adapters/vocabulary_tag_prefixes.py`) |
| naming | `unit_prefix` | `12-P-03A`, `U12-P-03A` | OPEN100 system-code prefixes (`RC`/`RCS`, `CND`, `CVCS`) |

`class_synonym` applies only to codes in its table; for any other class the naming draw uses `unit_prefix`.

**Invariants (property-tested over every v2 equipment type code):** every operator changes the string; every
operator keeps `node_class` and the order of non-zero digits (so the §5.2 key survives); no synonym equals a code the
same `node_class` already uses. Consequence, stated in the thesis: blocking completeness is 1.0 **by construction**
for these operators. It tests the implementation, not robustness; variants that change digits (a spare written as
`-1`, a renumbered tag) are a limitation, unchanged from ADR-0031.

### 3.3 Hard negatives v2 provides by itself

- **A/B spares** (`spare_naming = suffix`, ADR-0058): `P-1203A` vs `P-1203B`, same class, same key, same unit.
- **`unpad_sequence` ambiguity**: `P-123A` (unit 12, sequence 03) equals the canonical tag of unit 1, sequence 23,
  when that item exists. Only context (the unit) separates them.
- **Role codes inside one class**: `V-1203`, `R-1203`, `D-1203` are all `PressureVessel`.
- **Cross-unit collisions** of the key at 600+ units (461 "other" negatives at D1000g2, rate 0.25).

## 5. Candidates, card, deciders, grouping

### 5.1 Pair card (`resolution/identity_candidates.py`)

```
Occurrence A: tag "P-1203A"; class CentrifugalPump; sheet 41; unit 12; drawn next to: GTV-12107 (sends to, line 6-P-120017-A1A-N), PI-12031 (measured by)
Occurrence B: tag "12-P-03A"; class CentrifugalPump; sheet 42; unit not printed; units on sheet 42: 12; drawn next to: V-1201 (receives from, line 8-P-120004-A1A-N)
Sheets 41 and 42 are joined by 3 off-page connector pairs.
```

Built only from visible properties of localized sheets plus the resolver's own connector pairs; never ids, the
manifest or the variant draw. A = the occurrence with more properties (tie: lower sheet id). Neighbours: 1 hop, at
most 6, sorted by tag, with the incident edge's `line_number` when present.

### 5.2 Blocking

Over non-connector occurrences of `EQUIPMENT_CLASSES` with a tag; key = `(node_class, the tag's digits with every
"0" removed)`; pairs on **different sheets** in one block, excluding pairs already grouped by exact tag (as today).
Metrics (eval side): pair completeness, reduction ratio, candidate count. Revisit trigger (ADR-0031): completeness
< 0.99 on `D100g2d100Vf`.

### 5.3 Grouping (one rule added)

Exact-tag groups ∪ accepted links → union-find → `IdentityGroup`s; home = most properties, tie by sheet id
(unchanged). **New, one-to-one per sheet pair:** accepted links are taken in order of score (descending; tie: D1
score, then content key), and a link is dropped if either occurrence already has a link to an occurrence on the
other's sheet. Reason: an item is drawn at most once per sheet, the same principle as §4.6's same-sheet split, which
stays as the final check (`identity_conflicts` counted). This rule is what separates `P-1203A` from `P-1203B` when
both score above threshold.

Links are keyed by **content keys** `(sheet_id, tag, node_class)`, not occurrence ids, so a salted `localize` (gate
G2) maps them identically (`resolution/identity.py` already refuses keys ambiguous within a sheet).

### 5.4 Deciders (`PairDecider.decide(card) -> PairDecision(score: float, accept: bool)`)

| Id | Decider | Threshold | Where | Cost | Keep because |
|---|---|---|---|---|---|
| D0 | exact tag (today's resolver) | — | `resolution/` | free | the system as measured in R5; the E2E floor |
| D1 | normaliser (upper-case, keep `[A-Z0-9]`) + `difflib.SequenceMatcher` ratio | τ₁ on dev | `resolution/` | free | ADR-0031 option A: shows the circularity trap as a drop on the naming family |
| D2 | D1 score ≥ τ₂ **and** the units agree: A's printed unit (or its sheet's unit) is among the units printed on B's sheet | τ₂ on dev | `resolution/` | free | context without a model |
| D4 | chat LLM on the card, JSON `{"same_item": bool, "reason": str}`; score 1/0 | none | `exp0004/` | paid | the only model-based decider; uses context and general P&ID knowledge |

- D1's normaliser has no zero handling and no synonym table (either would encode an operator family).
- D2's context rule was fixed after the structural dev probe (§2: gold 93/93 same unit), which looked at no
  variant. The thesis states this, and that "references stay inside their unit" is a generator property: a
  cross-unit reference (a tank-farm item drawn on a unit sheet) would defeat D2.
- D4: the V2T-A Cypher-tier pin `data/runs/exp0007/inputs/pin_cypher_luna_low.json`, unchanged (one model,
  ADR-0014); the §10 cost basis comes from that tier's calls. The prompt
  states the task and one sentence of general practice ("installed spares share a number and differ by a trailing
  letter"); it lists no operator and no synonym. Prompt, card format and pin are hashed into the pre-registration
  before the first test call. A parse failure counts as "not accepted" and is reported; more than 2 % parse failures
  in the pilot means the prompt is fixed on dev before anything else runs.
- Cut: D3 and D5 (§1, ADR-0063).

### 5.5 Tuning without circularity

- τ₁, τ₂ maximise pair-level F1 (after §5.3) on `D100g2d100Vf` only (dev seed, format family only). Grid = every
  distinct score observed on that corpus. Ties → the higher τ (precision first).
- D4 has no threshold: nothing of it is tuned. Its prompt may be fixed on dev (parse failures only).
- The naming family is generated for the first time on the test corpora. No decider, prompt or threshold changes
  after the first test-corpus run; a defect found then is reported, not fixed.
- `D1000g2d100Vf` scores D0–D2 with the dev τ's, descriptively: does a 100-sheet threshold transfer to 1,000 sheets?

## 6. Scoring and pre-registered resolution claims

Per decider × corpus × family (and per operator, descriptive): pair-level P/R/F1 on the candidate set; group-level
P/R/F1 with `eval/resolution_scoring.py` `score_identity_groups`; blocking metrics; `identity_conflicts`; for D4
calls, cost (provider-billed), latency p50/p95, parse failures, cache hits. 95 % CIs by **cluster bootstrap over
blocks** (a block holds all pairs that compete with each other), 2,000 resamples, seed 20261104; differences between
deciders are paired on the same resampled blocks.

| Id | Claim (corpus `H1000g2d100V` unless stated) | Pass if |
|---|---|---|
| I0 (gate) | blocking keeps the gold links | completeness ≥ 0.99 on `D100g2d100Vf` (before any paid call) and on every test corpus |
| I1 (manipulation check) | the naming family is harder than the tuned one for the tuned string decider | F1(D1, format) − F1(D1, naming) > 0, CI lower bound > 0. If it fails, the held-out family is not a real held-out test and the thesis says so |
| I2 (context) | context without a model helps | F1(D2) − F1(D1), both families, CI lower bound > 0 |
| I3 (model on unseen variants) | the model generalises where tuned rules do not | F1(D4, naming) − F1(D2, naming), CI lower bound > 0 |
| I4 (scale, descriptive) | — | F1 at H1000 minus H100 per decider, with CI; candidate and cost elasticity `e = ln(c1000/c100)/ln(10)` |

Reasoned expectation, **not measured**: on format variants D1 and D2 are near 1.0 except `unpad_sequence`; on naming,
`class_synonym` scores about 0.92 and `unit_prefix` about 0.77–0.83 by `SequenceMatcher` (hand computation on
`P-1203A`, 2026-11-04), so a format-tuned τ near 0.91 rejects most `unit_prefix` variants. Nothing in the claims
depends on this guess.

## 7. End-to-end arm (EXP-0004-E2E)

### 7.1 Design

The frozen V2T-A system (`cascade_v4_iso`, both Luna tiers, setting A) runs the **sealed H1000g2 question set**
on `H1000g2V` loaded three times, once per resolver: D0, D2, D4 (links from §5 on that corpus). Baseline: R5's own
`S7-{CYP,AG}-H1000g2` (exact tags), already paid. All arms answer the same 560 questions; claims use R5's 440-question
headline scope.

| Id | Claim | Pass if |
|---|---|---|
| E1 (primary) | tag variants with today's exact resolver cost accuracy at plant scale | acc(V, D0) − acc(R5), paired bootstrap 95 % CI upper bound < 0 |
| E2 | D2 wins accuracy back | acc(V, D2) − acc(V, D0), CI lower bound > 0 |
| E3 | D4 wins accuracy back | acc(V, D4) − acc(V, D0), CI lower bound > 0 |
| E4 (non-inferiority, per D2 and D4) | the decider restores the headline | acc(V, Dx) − acc(R5), CI lower bound > −0.03 (0.03 ≈ the half-width of R5's own Wilson interval at H1000g2, 0.858–0.917) |

Paired bootstrap and acc@120 come from the existing EXP-0007 claims code; nothing new is computed by hand.

### 7.2 Why the sealed question set can be reused without breaking its seal

The seal protects one thing: R5's estimate of V2T-A's accuracy must not be biased by changes made after looking at
it. E2E keeps that intact:

1. **The system does not change.** V2T-A runs under freeze E8 (§8), proved identical to E7 by byte-identical replays.
   No V2T change follows from any E2E number (V2T development is closed, ADR-0061).
2. **Nothing is selected on the test questions.** τ₁, τ₂, the D4 prompt and the arm list are committed by the user
   before the first test-corpus call (pre-registration commit). All three arms run; none is picked afterwards.
3. **The questions are copied, not edited.** `exp0004 rehome-questions` writes a copy of
   `sealed/questions/H1000g2/questions.jsonl` with only `corpus_id` changed (the harness refuses foreign corpus ids,
   `qa/harness/question_set.py` line 24) and a proof file: every other field equal, `source_graph_hash` equal, manifest
   equal modulo reference tags. The original file and its T7 hash stay untouched.
4. **The sealed cache is read, never written.** Each arm starts from a **copy** of `sealed/cache_s7.sqlite`. An
   identical prompt replays R5's answer (what a deterministic system would do); a changed prompt is a paid call.
5. **R5 is never re-reported.** E2E is a separate results row; R5's numbers stay as recorded.

### 7.3 Why E2E is worth its cost (recommendation: H1000g2V only; H100g2V optional)

- It is the only measurement that turns "identity matters" into accuracy at plant scale: 112/560 questions are
  exposed at H1000g2 (§0).
- The cache makes unchanged questions free and pairs the arms exactly, so the differences are concentrated where
  identity changed.
- The claim is about plant scale; H1000g2 is R5's claims corpus. H100g2V (97/560 exposed) adds a second point for the
  same money again; it is the user's call (§12, Q1).

## 8. Freeze E8 (how V2T-A is shown unchanged after EXP-0004 code lands)

Verified 2026-11-04: `V2T_FROZEN_FILES` (`data/runs/exp0007/tune_lib.sh` lines 102–121) covers whole directories
(`benchmark`, `resolution`, `ingest`, `llm`, …) and `require_v2t_freeze` (`v2t_lib.sh` line 26) refuses on any diff
there, and on any file hashed in `E7.sha256` (which lists `splitter.py`, `split_models.py`, `ingest/*`, 9
`resolution/` files and `qa/corpus.py`). E2E needs data-side changes in those directories (variants, links,
ingest flags, the corpus rebuild in `qa/corpus.py`). So the E7 check cannot pass for E2E, by construction.

**E8 = ADR-0060 option 1B applied again:**
1. EXP-0004 changes only **data-side** paths: `benchmark/tag_variants.py` (new), `resolution/identity_*.py` (new),
   `resolution/resolver.py` (one optional argument, default = today), `ingest/pipeline.py`, `ingest/__main__.py`,
   `ingest/synthetic_setup.py` (flags, default-off), `qa/corpus.py` (rebuild honours the recorded variants and links).
   ADR-0060 already classes `ingest/` and `qa/corpus.py` as data-building. New paid code lives in
   `src/plantgraph/exp0004/`, outside every frozen path.
2. **No diff E7..E8 on the system-side paths** (ADR-0060's list: strategies, agent, plant API, prompts, cascade, need,
   `llm`, store, serializer, schema text, Neo4j view, final answer, harness). Cutting D3 and D5 is what keeps `llm/`

## 13. Threats to validity (stated in the thesis)

- Operators are ours; real variant distributions are unknown. The naming family is a held-out *kind*, not a sample of
  real variants. OPEN100's strings stay qualitative (five items, no graphml anchor).
- D2's unit rule leans on a generator property (references stay inside their unit).
- Completeness 1.0 is by construction for the chosen operators.
- Luna takes no temperature (ADR-0050); D4 decisions are cached and replayable, but a re-call may differ.
- E2E inherits R5's caveats (concurrency 4, Luna run-to-run variance, `LAT-CTRL-1`: 3/48 correctness flips).
